# Immortal Pet V2 当前玩法与开发路线

更新时间：2026-08-02。

本文是当前玩法状态的权威说明。代码实现与旧设计冲突时，以当前 `GameEngine`、存档结构和板级场景代码为准。

## 总体约束

- 权威状态只有修为、灵石、精力、进行中的活动、可信时间锚点、历练战斗状态和装备状态。
- 境界与层数由累计修为推导，不单独保存；不引入经验、等级、心情、羁绊或材料。
- 数值变化先写入候选状态，NVS 提交成功后才替换运行状态和刷新 UI。
- AI、语音、动画和场景只表达结果，不计算奖励，不直接修改权威状态。
- TF 卡保存首页、修炼、历练、兵器铺和人物动画等运行资源；重型场景按进入/退出管理资源。
- 可信时间来自网络校时和 PCF85063 RTC。时间无效或检测到回拨时，不开始或结算定时活动。

## 当前状态模型

存档版本为 V6，保存：

- 修为、灵石、精力和精力恢复锚点；
- 当前活动及开始、结束时间；
- 修炼事件与确定性种子；
- 历练关卡、怪物序号、通关位、战斗种子、出发修为、双方生命和回合数；
- 已拥有装备位图、当前武器和当前套装。

V3 历练存档缺少生命与回合数据，升级时不会恢复旧历练；V4、V5 会校验并迁移到 V6。

## 境界显示

- 修为 `0` 时隐藏境界名称、层级图和进度条。
- 修为 `1` 从炼气一层开始。
- 每累计 `100` 修为提升一层，每个境界 `15` 层。
- 境界依次为炼气、筑基、金丹、元婴、化神、合体、大乘、渡劫。

## 已实现：洞府首页与修炼

- 首次建档选择男修或女修并持久化。
- 首页加载 TF 卡洞府日夜背景、分层人物、菜单和境界素材。
- 精力上限 `100`，每 `5` 分钟恢复 `1` 点。
- 修炼持续 `5` 分钟，开始消耗 `10` 精力。
- 修炼完成自动结算，不提供手动领取按钮。
- 基础修为收益为 `10`；顿悟增加到 `16`，心魔降低到 `7`。
- 重启后依据可信时间恢复未结束修炼；到期只允许结算一次。

## 已实现：青岚灵墟历练与自动战斗

当前只开放关卡 `stage_id = 1`：青岚灵墟。

- 当前设备测试消耗为 `1` 精力，活动时长为 `3` 分钟。
- 出发时保存战斗种子、出发修为、双方生命、怪物序号和回合数。
- 怪物依次为柳鬼、桃精、青龙；每次击败后立即保存并发放对应灵石。
- 通关没有额外奖励；失败或超时只清除活动，保留已经提交的灵石。
- 战斗动画按块加载当前角色或怪物动作，退出历练后恢复首页绘制和音频服务。
- 历练角色会读取当前性别、套装和武器流派；140 级以上自带武器套装不叠加独立武器层。
- 重启时如果活动仍有效且时间可信，会恢复当前怪物和战斗状态。

详细公式和怪物参数见 [历练关卡设计](journey-stage-design.md)。

## 已实现：兵器铺与装备

- 首页第四入口已经接入兵器铺。
- 商店共 `32` 件物品：`22` 把武器和 `10` 套法衣。
- 武器分为金系枪和火系扇，每个外观档位各一把。
- 未拥有物品需要满足修为门槛并消耗灵石；购买成功后立即保存并设为当前装备。
- 已拥有物品可以免费切换；武器和套装分别记录当前装备。
- 首页启动时按当前装备加载分层外观；历练进入时直接读取当前装备加载战斗外观。
- 当前商店操作后会更新存档、商店状态和数值显示；洞府人物外观要到下次重新加载人物资源时更新。

装备定义包含 `combat_bonus`，`GameEngine::EquipmentCombatBonus()` 也已实现，但当前历练伤害公式尚未调用该加成。文档和 UI 不应把装备加成描述为已经影响战斗伤害。

## 下一步

1. 将装备加成接入确定性历练公式，并补齐对应规则测试。
2. 商店购买或切换装备后，无需重启即可安全重载洞府人物外观。
3. 完成青岚灵墟实机回归：套装/武器动画、伤害 HUD、重启恢复、超时和资源释放。
4. 在第一关稳定后再增加更多关卡、怪物和奖励表。
5. 继续实现札记、角色表达和长期稳定性验证。

## 已废弃方案

早、中、晚三时段行动、休息加成、同日收益递减、独立经验/等级、每境界十层和手动领取奖励均不再使用。旧计划只作历史记录。
