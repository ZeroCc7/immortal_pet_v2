# 洞府首页实现进度

更新时间：2026-08-02。

## 已实现

- 固定适配 Waveshare ESP32-S3-Touch-AMOLED-2.16 的 480×480 显示。
- 洞府日夜背景、分层人物、菜单、境界标题和徽章从 TF 卡加载。
- 首次建档选择男修或女修并写入 NVS。
- 人物身体和武器保持独立 LVGL 图层，同步待机、行走和方向。
- 根据当前装备选择火系/金系人物资源、套装档位和枪/扇武器。
- 140–170 档套装自带武器，不叠加独立武器层。
- 首页日期/时间使用 UTC+8 的可信时间；18:00–07:00 使用夜景。
- 精力、修为推导境界、Wi-Fi、TF 卡和电量状态已接入首页。
- 首页四个入口为修炼、历练、札记和商城/兵器铺。

## 场景资源生命周期

- 修炼、历练和兵器铺均使用独立场景对象。
- 进入历练时暂停首页人物、背景和自主行为定时器；退出后恢复。
- 历练期间停止音频服务，退出后延迟恢复，避免与大块 TF 卡读取争用。
- 替换人物资源时先完整加载新身体和武器，再切换当前对象；加载失败保留旧形象。

## 当前限制

- 商店购买/切换后，存档和商店 UI 会立即更新；洞府人物需要下次重新加载人物资源才显示新外观。
- 历练进入时直接读取最新装备，因此战斗外观不受上述限制。
- 装备 `combat_bonus` 尚未进入历练伤害公式。
- TF 卡缺少核心资源时显示安全页或取消场景，不使用不完整资源继续活动。

## 实机验收

- 检查四个入口点击区域和场景返回流程。
- 分别验证男/女、枪/扇、70–130 独立武器套装和 140–170 自带武器套装。
- 多次切换首页、修炼、历练和商店，确认没有持续 PSRAM 下降或看门狗复位。
- 本轮完整编译、烧录和硬件验证由项目所有者在 VS Code 中执行。
