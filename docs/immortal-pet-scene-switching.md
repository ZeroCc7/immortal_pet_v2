# Immortal Pet 多场景切换规范

本文档以“洞府待机 ↔ 修炼”已在设备上验证通过的实现为基线。后续游历、战斗、突破等全屏场景必须遵循同一套资源所有权和切换顺序。

## 核心原则

1. 首页与活动场景的 LVGL 对象不能复用。活动场景创建自己的根对象，并置于首页之上；首页对象只暂停和隐藏，不删除、不换图源。
2. 每个场景独占其背景、人物、特效和计时器。场景退出时先停止计时器，再删除根对象，最后释放该场景资源。
3. 背景只加载当前需要的一张。例如昼/夜背景只保留当前时段的那张，切换场景时不同时常驻两张。
4. 动画使用固定数量的缓冲区。修炼人物保留“当前帧 + 下一帧”两张 256×256 ARGB 缓冲；下一帧从 TF 覆写未显示缓冲，随后才切换 LVGL 图源。
5. 低频或条件特效延迟加载。顿悟帧只在顿悟出现时加载；退出场景后全部释放。
6. 场景素材加载失败必须回滚到原场景，恢复首页对象和定时器，不能留下半隐藏的界面。

## 代码规模约束

- 主板实现文件应控制在 **1500～2000 行**；超过 2000 行时优先提取场景、首页 HUD 或资源加载职责。
- 单个板卡专属模块建议控制在 **300～600 行**；超过 800 行时必须评估是否混合了资源、UI、计时器和状态转换等多种职责。
- 主板文件只保留硬件初始化、首页协调和模块间的窄调用；不得重新堆入场景对象、动画计时器或 TF 资源读取细节。

## 场景状态与所有权

```text
首页（常驻）
  scene_ / 洞府背景 / 待机人物 / 武器层 / 首页计时器
       │ 进入活动：暂停计时器、隐藏人物和按钮
       ▼
活动覆盖层（短生命周期）
  activity_scene_root_
    ├─ 当前时段背景
    ├─ 活动人物图像
    ├─ 条件特效图像
    └─ 倒计时或状态文本
       │ 退出：暂停活动计时器、删除根对象、释放活动资源
       ▼
首页（恢复）
  显示人物和按钮，恢复待机计时器
```

首页人物、境界图片、倒计时文字都不得作为活动场景的子对象或图源。这样活动动画不会写入待机人物，也不会把人物帧误显示到境界图片上。

## 标准切换顺序

### 进入活动场景

1. 若已有活动覆盖层，直接拒绝重复进入。
2. 暂停首页动画、行走、自主行为和延迟恢复计时器。
3. 隐藏首页人物、武器和操作按钮；不要释放首页资源。
4. 加载活动所需的最小资源集；失败时执行“退出活动场景”回滚。
5. 创建活动根对象及其背景、人物、文本、特效对象。
6. 启动活动动画计时器，并将活动根对象移到最前。

### 活动中

1. 计时器只更新活动根对象内的图像。
2. 先读取或准备未显示缓冲，再调用 `lv_image_set_src()` 切换到该缓冲。
3. 条件特效第一次出现时再加载；加载失败时保持主动画，不影响活动状态。

### 退出活动场景

1. 暂停活动动画计时器，避免计时器访问已删除对象或已释放图像。
2. 删除活动根对象，并将其所有子对象指针置空。
3. 释放活动背景、动画缓冲和条件特效资源。
4. 显示首页按钮和人物，恢复待机、自主行为等首页计时器。

## RAM 预算基线

以 480×480 RGB565 背景和 256×256 ARGB8888 人物帧计算：

| 场景资源 | 缓冲数量 | 原始像素内存 |
| --- | ---: | ---: |
| 当前背景 | 1 | 460,800 B |
| 主动画双缓冲 | 2 | 524,288 B |
| 普通修炼合计 | — | 985,088 B（约 0.94 MiB） |
| 顿悟特效（触发后） | 4 | 1,048,576 B |

不要回退到“昼夜双背景 + 全部主动画帧 + 全部特效帧”同时常驻的方式；该方式约需 3.38 MiB 原始像素内存。

## 现有实现入口

- 修炼资源与双缓冲：`firmware/device/main/boards/waveshare/esp32-s3-touch-amoled-2.16/immortal_pet/cultivation_assets.*`
- 修炼场景生命周期：`CustomLcdDisplay::EnterCultivationScene()`、`ExitCultivationScene()`。
- 新场景应创建同级的板卡专属模块，不继续向 `esp32-s3-touch-amoled-2.16.cc` 堆叠资源读取逻辑。

## 新场景验收清单

- 待机进入新场景后，背景、人物、境界和按钮没有串图或闪动。
- 条件特效出现和消失不会影响主动画。
- 退出后待机人物恢复规则、行走和自主行为正常。
- TF 素材缺失或读取失败时，首页完整恢复且活动状态不会卡死。
- 冷启动恢复活动失败时，同样回退到完整首页。
- 记录进入前、活动中、退出后的可用 PSRAM，确认活动资源已释放。
